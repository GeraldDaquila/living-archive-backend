# USE v334 Lean Generation Envelope — Controlled Implementation

## Objective

Make the real provider-generation path executable by removing duplicated fixed prompt instructions while preserving the evidence already selected upstream.

The current live failure is not an evidence-selection failure. Production logs show provider preflight rejecting the request before provider execution because the fixed system/user envelope is approximately 4.6K characters.

## Required design

The lean envelope is a compact operational contract, not a replacement for the constitutional source.

It must preserve these functions:

1. Answer the visitor's actual question directly.
2. Use supplied canonical Content as the substantive evidence authority.
3. Preserve exact canonical title identity; URLs remain deterministic link authority outside the model.
4. Preserve the adjudicated recommendation as the primary doorway for recommendation requests.
5. Permit distinct supplied companion evidence when the question genuinely benefits from more than one route.
6. Preserve evidence-bound synthesis and explicit inferential-distance limits.
7. Preserve frame sovereignty: do not impose a specialized worldview or visitor state that the visitor did not name.
8. Preserve non-advisory navigation: describe Archive lenses and routes, not prescriptions for the visitor.
9. Preserve compassionate vulnerable-experience boundaries.
10. Return only the finished visitor answer in the required output structure.

## Explicit grief invariant

For grief, bereavement, death, loss, or comparable vulnerable-experience questions, the lean envelope must prohibit asserting that an Archive resource offers or provides comfort, healing, peace, closure, meaning, purpose, hope, or another visitor benefit. Source material may be described as containing or exploring such themes when the supplied Content establishes that.

## What must not be cut

Do not reduce or rewrite retrieval, canonical evidence selection, question-specific resource authority, recommendation authority, protected primary evidence, URL/title provenance, D29 movement validation, final safety validation, or deterministic canonical-link reconstruction.

Do not solve the size problem by shrinking the evidence window first.

## Implementation principle

The fixed generation prompt should be treated as a minimal executable policy layer. Rules already enforced deterministically by the engine should not be repeated at full constitutional length in the provider prompt.

The provider therefore receives only the behavioral constraints it must actively follow while generating language. Deterministic boundaries remain in Python.

## Measurement gate

Before any production promotion, measure the actual assembled empty-evidence prompt and the final fitted request using the same `_estimate_message_chars()` and provider preflight logic.

The known grief recommendation query must produce a provider-executable request with substantive evidence capacity remaining. The benchmark-quality answer is the target; the deterministic fallback remains the safety floor only.
